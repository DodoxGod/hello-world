## 5. Rules and gotchas

- Test runs rewrite `docs/EQUILIBRIO.md` (also `MATERIALES.md`, `MEJORAS.md`): `git checkout -- docs/EQUILIBRIO.md` the noise; commit it only when its content really changed (new material etc.).
- Preserve line endings (files are mixed CRLF/LF): before committing, `git diff --stat` must equal `git diff --stat --ignore-cr-at-eol`.
- `CHANGELOG.md` is newest first: new entry at the top, `## YYYY-MM-DD — title`.
- Code and comments in English. Commit messages in Spanish, ending with the Co-Authored-By line the session gives.
- Balance tests (`BalanceGameTests`, `ArmaduraGameTests`, ...) guard thresholds: fix the content (stats, numbers), not the threshold, unless a design doc says the threshold may move.
- `docs/red_mob_v4_mod_estado.md` is the contract with the simulator team: any change to mob-AI rules, observations or outputs (`J/ai`) must be noted there. Contract JSONs and net names are frozen (`RedV4GameTests.v4NamesMatchTheContract`).
- Never swap the Modrinth forja jar while Minecraft runs (crashes it). Check first in PowerShell: `Get-Process javaw,java -ErrorAction SilentlyContinue | Select-Object Id,MainWindowTitle,Path`; swap only if no Minecraft process is running.
- Agents work in git worktrees and **never push** or merge; another session may share the tree: check `git status` before touching shared files.
- Generated files (lang, equipment, recipes, kits, castle .nbt, `forja_arboles.json`): change the generator and rerun it, never hand-edit.
- Lang/book texts that say what a far forge melts must be updated whenever an alloy is added (`tools/lang_aleaciones.py`).
